# Journalism standards check — run 71

## Standards researched (WebSearch)
1. **AP corrections policy** (AP Statement of News Values and Principles, Poynter
   commentary on wire-service error propagation): errors must be corrected "fully,
   quickly and ungrudgingly"; lengthy stories should carry an editor's note with
   enough methodology/attribution detail for a reader to assess veracity.
2. **Reuters sourcing hierarchy** (Reuters Handbook of Journalism / Essentials of
   Reuters Sourcing): named sources > unnamed; never cite sources "in the plural"
   when there is only one; clearly attribute information to its source; report
   facts, not rumor, and be explicit when something is unconfirmed.

## Gap-check against this project

**Corrections mechanism (report_schema.py `save_report`/`revision_history`):**
Checked against AP's "fully, quickly, ungrudgingly + visible to the reader" standard.
Result: **no gap, already matches or exceeds the standard.**
`web/app/reports/[date]/page.tsx` (lines ~272-290, 611-624) renders a visible red-bordered
"Corrected {date}: {reason}" banner near the top of the page (not buried in a footer) plus
a full correction-history section further down, sourced directly from
`revision_history`/`corrected_at`. This was itself flagged and fixed in a prior audit
(referenced in the component's own comment: `docs/agent-logs/journalism-standards-check-run40.md`
— run 40 already did this exact AP-corrections-visibility check and shipped the fix). Nothing
further to add: schema requires non-empty reason + corrected_at, and it's genuinely rendered,
not just data-only (avoiding the project's known "populated but not shown" bug pattern).

**Sourcing/confidence language — spot-checked 2 most recent reports
(2027-09-13.json, 2027-09-06.json)** against Reuters sourcing-hierarchy conventions.
Result: **matches the standard, no gap found.**
- Sources are named and attributable at the outlet-domain level (`source_domains`:
  cfda.com, wwd.com, businessoffashion.com, fhcm.paris, laforma.club) — no vague
  "sources say."
- Single/limited corroboration is held to appropriately low/medium confidence rather
  than inflated. The 2027-09-06 report explicitly declines to treat two "unclear"-sector
  domains as genuine cross-sector corroboration, reasoning in `human_editor_note` that
  doing so would exploit a taxonomy gap rather than reflect real independent confirmation
  (Reuters: don't overstate source plurality/independence).
- Absence-of-evidence is explicitly distinguished from confirmed fact: the 2027-09-13
  report's `human_editor_note` states a "no schedule found" result is held at low
  confidence rather than the "high" `derive_confidence()` would compute, because a negative
  search result isn't equivalent to independently-confirmed positive corroboration, and
  flags the residual possibility that a schedule exists but wasn't surfaced.
- `limitations` fields in both reports state plainly what could not be determined,
  matching AP/Reuters' "state uncertainty rather than paper over it" convention.

## Overall finding
Genuine clean result on both fronts checked — no schema, rendering, or prose gap found.
This project has already run an equivalent corrections-visibility audit before (run 40)
and the current reports show sourcing discipline consistent with wire-service norms
(named domain attribution, confidence held down rather than inflated on ambiguous
corroboration, explicit absence-of-evidence framing). No action items generated by this run.
